## Unapproved decisions

Reference devices/apps, candidate dictionary licensing, voice-provider network acceptance, product-image ownership/cache retention, exact compact target exception, stale-product policy, whether to re-enable currently deferred template sync, and seller-app test accounts remain `[needs confirmation]`. `docs/product-decision-proposal.md` and `docs/product-decisions.proposed.json` now record ten implementation-matched recommendations and the exact approval procedure. The verifier accepts them only through a complete `sellerkeyboard-product-decisions-v1` approval record; a generic release exception cannot approve product choices. They do not invalidate completed static work, but the affected release rows cannot pass without recorded decisions and evidence.

Release-evidence exceptions are also machine-validated. `docs/release-exceptions.example.json` documents the `sellerkeyboard-release-exceptions-v1` structure; approvals require an accountable approver, narrow rationale/scope, and an unexpired timestamp. Plain text containing a blocker ID is no longer accepted as a waiver.
