## Macrobenchmark status

The first device attempt revealed that `benchmark-benchmark.apk` was unsigned and failed with
`INSTALL_PARSE_FAILED_NO_CERTIFICATES`. The benchmark-only test variant now uses debug signing and
builds successfully.

The initial activity target lived in the SellerKeyboard package. Macrobenchmark's cold-start setup
therefore force-stopped the IME package and Android silently selected Gboard. That invalid run was
discarded. The corrected benchmark uses the separate neutral `:benchmark-host` APK, asserts the
selected component before every iteration, and ends a synchronous trace section only when the host
receives visible IME insets.

Both IME packages are normalized to Android ART `speed` compilation before tracing so the comparison
does not favor Gboard merely because it is an older Play installation. The final authoritative UTP
run (ten cold iterations per IME on the identical neutral host) produced:

| IME | Host `onCreate` → visible IME median | Min–max | Host initial-display median |
|---|---:|---:|---:|
| SellerKeyboard | 42.861 ms | 37.935–57.123 ms | 621.008 ms |
| Gboard 17.7.4 | 41.187 ms | 39.301–48.019 ms | 611.696 ms |

SellerKeyboard/Gboard visible-IME ratio is `1.0406×`, below the `1.25×` goal threshold. This trace
boundary is a reproducible host-lifecycle-to-visible-insets proxy; it does not claim to measure an
undocumented internal Gboard readiness event. The verifier now parses benchmark JSON and fails when
the ratio exceeds `1.25×`.

The corrected 100-cycle SellerKeyboard Macrobenchmark (five batches × 20 show/hide cycles) passed:

- frame-duration CPU p95 `13.295 ms`, p99 `19.083 ms`, sampled maximum `85.499 ms`;
- frame-overrun p99 `7.104 ms`;
- max heap per batch `5,410–5,774 KiB` and max anonymous RSS `20,092–21,528 KiB`, with no
  monotonic growth across the five batches;
- median `167` measured frames per batch.

The authoritative raw output, JSON, threshold report, and Perfetto traces are under
`docs/evidence/verification/latest/connected-macrobenchmark.log`,
`docs/evidence/verification/latest/connected-macrobenchmark-output/`, and
`docs/evidence/verification/latest/macrobenchmark-thresholds.json`. Earlier direct-run artifacts are
retained as exploratory evidence but are not the release number source.
